# Group-wise Temporal Reliability Guided Adaptive Execution Horizon

**Status:** method prototype and offline-validation scaffold. No rollout is
run by this package, and no success improvement is claimed.

## Formulation

The base ACT policy remains frozen:

\[
\hat A_t = \pi(o_t) = [\hat a_{t|t}, \ldots, \hat a_{t+H-1|t}].
\]

For action group \(g\) and offset \(k\), the auxiliary estimator consumes
source-time information and predicts

\[
\hat R_g(k \mid o_t, \hat A_t, g) =
P(Y_g(k)=1 \mid x_t, \hat A_t, g, k),
\]

where \(Y_g(k)\) is the precomputed temporal-validity target. The feature
encoder uses only the source observation embedding placeholder, source chunk
statistics, group ID, and offset. Future observations are target-only.

The first implementation uses a small MLP with a single sigmoid output. It is
not a horizon classifier and is not trained on rollout success.

## Existing target

The fresh-policy persistence target compares the source chunk's group action at
offset \(k\) with the first group action of a fresh frozen-policy prediction at
the future observation \(t+k\):

\[
\ell_g(t,k) = d_g(\hat a^g_{t+k|t},
                  \hat a^g_{t+k|t+k}),
\qquad
Y_g(k) = 1[\ell_g(t,k) \leq \epsilon_g].
\]

The threshold \(\epsilon_g\) is supplied by the existing configurable target
generator. It is not inferred from rollout success and is not re-generated by
the training/evaluation scripts. The separate demonstration-deviation target
remains available as a diagnostic, but must not be mixed into the primary
target without a predeclared study.

## Episode split and training

Examples inherit a split made on episode IDs before temporal examples are
expanded. The intended LIBERO Object paths are recorded in
`configs/default.json`; the current checkout does not contain those external
paths, so no real checkpoint or target artifact is produced here.

The train command consumes a prepared `.npz` artifact containing source-only
features, precomputed labels, group/offset metadata, and train/validation/test
assignment. It trains with binary cross entropy on logits, early-stopping on
validation BCE, and writes one checkpoint for each ablation:

- `combined`: arm and gripper rows in one model with group ID;
- `arm`: arm rows only;
- `gripper`: gripper rows only.

The frozen ACT checkpoint is never updated. The MLP is deliberately small and
does not receive future observations, episode outcomes, or benchmark success.

The commands are module entry points from the repository root:

```sh
PYTHONPATH=src:. python -m experiments.dynamic_reliability_horizon.train \
  --dataset /path/to/prepared_reliability.npz \
  --output-dir experiments/dynamic_reliability_horizon/checkpoints

PYTHONPATH=src:. python -m experiments.dynamic_reliability_horizon.evaluate \
  --dataset /path/to/prepared_reliability.npz \
  --checkpoint experiments/dynamic_reliability_horizon/checkpoints/reliability_mlp_combined.pt \
  --mode combined \
  --output-dir experiments/dynamic_reliability_horizon/evaluation
```

## Horizon decoder

Given a group reliability curve, the default decoder uses a strict threshold
`tau`:

\[
h_g(t) = \max\{k+1 : \hat R_g(k) > \tau\}.
\]

The `+1` converts a zero-based valid offset into an action count. By default,
decoding requires a contiguous valid prefix; this prevents an isolated high
score after a failed offset from extending open-loop execution. If no score is
above threshold, `min_horizon` is used as a conservative fallback. Both the
threshold and horizon bounds are configurable. A non-prefix mode is available
for diagnostics only.

## Adaptive execution adapter

`AdaptiveGroupwiseExecutor` keeps one buffer, cursor, source generation, source
age, and remaining commitment per action group. When one or more groups expire,
it queries the frozen policy once, asks the scheduler for a new horizon curve,
and refreshes only the expired groups. Non-expired groups retain their prior
source chunk and cursor. It emits the existing `one_clock.ExecutionDecision`
record, preserving the verified arm indices `0:6`, gripper index `6`, and full
chunk query semantics.

The production executor is not modified. Static global/groupwise baselines
continue to use `FixedChunkExecutor`; the adaptive adapter is not wired into
benchmark rollout scripts until offline validation passes.

## Progressive evaluation

Evaluation is intentionally ordered:

1. estimator discrimination and calibration: AUROC, Brier score, ECE,
   reliability diagrams, and offset calibration curves;
2. offline horizon decoding and schedule summaries for fixed static, learned
   reliability, and oracle reliability curves;
3. only after those checks, a controlled rollout integration audit.

The estimator is compared against a constant train-set prior and an empirical
train-set \(P(Y=1\mid g,k)\) reliability curve. No offline horizon analysis
is a task-success result: it reports decoded horizon distributions and does
not establish that dynamic horizons improve robot performance. The offline
schedule report contains four explicit sources when requested: global fixed,
static group horizons, learned reliability horizons, and label-oracle
reliability horizons. The last is an upper-bound diagnostic using held-out
validity labels, not a deployable controller.

## Limitations

- Fresh-policy disagreement may measure policy indecision rather than control
  validity.
- The placeholder observation embedding carries no visual information until a
  frozen, source-time-compatible encoder is supplied.
- The raw target metric must be replaced or calibrated with group-aware action
  normalization before scientific conclusions.
- A probability threshold does not guarantee a safe horizon, and per-group
  marginal reliability does not guarantee mixed-generation joint consistency.
- Episode-level splitting prevents frame leakage but does not establish task or
  embodiment generalization.
- No rollout success, dynamic-horizon benefit, or robot improvement is claimed
  until the estimator and schedule pass held-out offline checks and a separate
  controlled rollout study.
